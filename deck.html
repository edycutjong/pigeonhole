Open on the animation, don't talk over it for the first three seconds. Then: "This is Pigeonhole. Every invoice gets an address that is pure arithmetic — nothing is deployed until it is paid, and when it is swept, the contract that did the sweeping is already gone. It is live on Arc mainnet today."
Read the code line out loud; it is Circle's, not ours. Point out that this is the reference every exchange copies onto Arc: HD wallet in Step 1, a signer with the deposit key in Step 6. The question we asked was simply: why does a deposit address need a key at all?
Walk the boxes left to right. Each one is operational surface: the seed, the derivation, the key store, the online signer, the fee arithmetic — and the worker that has to leave gas behind, so it can never sweep the whole balance. This is a composite role, not a named customer; the pain is from Circle's own guide.
Same canvas, two boxes. The address is a hash of the factory, the invoice id and the treasury — it exists before any contract does, and anyone can hand it out with no transaction. When it's paid, anyone may call sweep. Funds can only reach the immutable treasury: there is no admin path, no parameter, no owner.
This is the slide to remember. The sweep transaction deploys 22 bytes at the address, its constructor moves the whole native balance and self-destructs, and EIP-6780 deletes the account in the same transaction. Code goes back to 0x, nonce to zero, and the address can be paid and swept again — we proved that on mainnet.
Four properties, and the mechanism needs all four. The load-bearing one is the first: on Arc, USDC is the account balance itself, which is what SELFDESTRUCT moves. On Ethereum or Base the USDC lives inside a token contract, so the same 22 bytes would move nothing and the emitter would log nothing.
Everything on this slide is read live from chain 5042. The invoice page derives SWEPT from logs and cross-checks the balance on every poll. The reviewer page is the 60-second path with the receipts. The explorer capture is the re-sweep: a contract created and destroyed in one transaction, rendered logged-out.
This is the page's own readout, monospace and unedited. One filter on the system emitter gives both movements. The invariant line is the part to stress: the sum of logs equals the balance the RPC reports, checked every three seconds — if an indexer ever disagreed with the chain, this page would show it.
Every number here has a file behind it in the repo — bench rows, test names, the bytecode recipe. The explorer would not accept source verification through its Cloudflare wall, so we compared the on-chain runtime code byte for byte with the build instead. "npm run verify" reproduces the prediction and the invariant with no wallet.
We would rather you hear these from us. The treasury is immutable on purpose — that is what makes "funds can only go one place" true — and it is also the single thing that could freeze every unswept invoice. Latency was not measured, so it is not claimed.
Pigeonhole is the first proof that Arc's native-USDC model supports payment primitives that need no keys and no keepers. The same foundations give standing orders, exactly-once payments and card-style holds. The near-term product is a hosted deposit-address API for exchanges and PSPs — that is the Circle Grant Program conversation.
Scan the code — that page needs no wallet and no login. The ask is small and specific: one microgrant, an office-hours session with the Arc team on the emitter and finality semantics, and the route into the grant program. Everything shown today is on mainnet and reproducible from the repo.
